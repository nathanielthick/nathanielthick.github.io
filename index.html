Adapter Lookup

A Windows app that makes a shared Microsoft Access database of 2,000+ test adapters searchable by connector, pinout, insert arrangement and part number. Engineering uses it to reuse existing hardware, and Cost Estimating uses it so customers aren't charged for adapter parts already on hand.

  • Instant search across every column with multi-word matching and wildcards, plus range filters, pick-lists and removable filter chips
  • Editing is off by default, with undo for every change, a backup offered before the first edit, and a CSV change log of who changed what
  • Refuses an edit if someone else changed that row in the meantime, and ships as a single .exe so teammates don't need Python

Wirelist Convertatron

Converts customer CSV wire lists into Cirris test programs, translating connector and pin labels into tester points. It replaced manual test programming, cutting programming time and the transcription errors that came with it.

  • Paste or open the wire list and label list, edit them in place, and set the resistance written on every wire
  • Unknown points, malformed lines and conflicting labels are listed in a Messages tab, and everything else still converts
  • Ships as a Windows app through GitHub Releases, with a command-line version for batch jobs and scripting

04 About

A generalist who likes the unglamorous problems

I'm based in Southern Oregon and studied Computer Science at Oregon State. I like knowing how things work all the way down: from logic gates and assembly up through operating systems, databases and the web.

My work has covered most sides of a business's technology: software and manufacturing internships, on-site hardware repair, running IT and e-commerce for a growing company, building websites on contract, and test engineering for electronics. The thread through all of it is the same. I find the slow, manual or error-prone part of a process and build something that fixes it.

The problems I enjoy most sit between people and systems: the database only one person knows how to query, the spreadsheet nobody wants to touch, the storefront that needs to actually bring in sales.

01

Build for the person using it

Plain language, keyboard shortcuts, and documentation that makes sense without me in the room.

02

Make mistakes hard to make

Safe defaults, undo, backups and change logs, so a tool earns trust instead of demanding it.

03

Ship something useful, then improve it

A small working version in people's hands first, then changes based on how they actually use it.
